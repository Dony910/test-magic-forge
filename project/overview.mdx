# GDD

## 1. 게임 개요

**마법공방의 대장장이 (Magic Forge)**는 동서양 판타지와 무협이 교차하는 세계에서 손님의 의뢰를 해석하고, 원소와 스케치로 맞춤 무기를 제작하는 상점 경영 게임입니다. 프로젝트 코드명은 **Project FORGE**입니다.

## 2. 플레이어 판타지

플레이어는 영웅을 직접 조종하지 않습니다. 차원의 교차로에 위치한 대장간의 대장장이로서 손님의 사연을 듣고 필요한 무기를 추론하며, 제작 결과로 손님의 운명에 간접적으로 개입하는 **관찰자이자 조력자** 역할을 수행합니다.

## 3. 핵심 재미

1. **의뢰 해석**: NPC의 대화에서 필요한 무기의 성질과 형태를 추론한다.
2. **창작 제작**: 원소를 물감처럼 사용하고 직접 스케치해 의도를 표현한다.
3. **결과 확인**: AI가 생성한 무기와 의뢰 요구의 일치도를 평가받는다.
4. **후일담**: 제작한 무기가 손님의 모험에 어떤 결과를 만들었는지 확인한다.

## 4. 코어 루프

```text
NPC 방문
→ 대화 및 의뢰 해석
→ 제작 진입
→ 무기 대종류 선택
→ 보유 원소 팔레트에서 스케치
→ 로컬 형태 분석 및 AI 무기 생성
→ 무기 전달
→ 태그 기반 평가/보상
→ 후일담
```

## 5. 핵심 규칙

- 플레이어는 **무기 대종류만 선택**하고 세부 종류는 시스템이 자동 판정합니다.
- 보유한 사용 가능 원소 전체를 팔레트에 표시하며 **사전 원소 보관 단계는 사용하지 않습니다**.
- 한 제작에서 실제 사용할 수 있는 서로 다른 원소 종류 수는 N개로 제한합니다.
- 스케치 해석에는 VLM을 사용하지 않습니다.
- NPC 의뢰와 완성 무기는 태그 데이터를 가지며, 태그 유사도를 평가 점수의 핵심 입력으로 사용합니다.

## 6. 주요 시스템 지도

| 시스템 | 책임 |
| --- | --- |
| 의뢰/내러티브 | NPC 대화와 요구 조건 전달 |
| 태그 | 의뢰와 무기의 내부 의미 표현 및 유사도 평가 |
| 원소 | 무기 제작 재료와 생성 테마 입력 |
| 무기 제작 | 대종류 선택, 원소 스케치, 제작 세션과 결과 확정 |
| 스케치 분석/AI | 벡터 입력을 수치 특징으로 변환하고 결과 생성에 사용 |
| 무기 | 무기 종류, 파츠 구조와 조립 규칙 정의 |
| 후일담 | 제작 결과에 따른 NPC 결과와 보상 회수 |

## 7. 스케치 분석 원칙

```text
벡터 스트로크
→ 로컬 래스터화
→ OpenCV/수학 특징 추출
→ 구조화 JSON
→ 로컬 텍스트 LLM
→ 무기 생성 모듈
```

계산 가능한 정보는 로컬 전처리에서 먼저 계산하고 LLM은 의미 해석·분류·생성에 집중합니다.

## 8. MVP 범위

### 포함

- NPC 의뢰 수신 및 요구 추론
- 태그 기반 의뢰/무기 평가
- 보유 원소 기반 스케치
- 무기 대종류 선택 및 세부 종류 자동 판정
- VLM 없는 로컬 스케치 분석
- AI 무기 생성 및 결과 확정
- 실패 시 입력 유지 및 재시도

### MVP 외부 또는 별도 확정 필요

- 원소 시너지/상극/혼합
- 생성 결과 후보 비교 및 부분 수정
- 원소 거래, 숙련도, 랭킹
- 상세 경제·성장·후일담 밸런스

## 9. 시스템 간 의존성

- 의뢰 시스템은 태그 시스템에 요구 태그를 전달합니다.
- 제작 결과는 평가 가능한 무기 태그를 포함해야 합니다.
- 제작 시스템은 원소, 무기, 스케치 분석 시스템을 참조합니다.
- 후일담은 평가 결과를 입력으로 사용할 수 있습니다.

## 10. 문서 기준

이 GDD는 게임 전체의 경험과 시스템 관계만 정의합니다. 개별 시스템의 세부 규칙, 구현 상태, 데이터 계약은 각 시스템 기획서 및 기능정의서를 기준으로 합니다. **기획 정책과 구현 상태는 서로 다른 정보이며 구현 상태만으로 기획 정책을 변경하지 않습니다.**
