# Decision Log

## 완료된 결정

### D-001 원소 사전 보관 폐기

**결정:** 무기 제작 전에 사용할 원소 N종을 미리 보관하는 구조를 사용하지 않습니다. 제작 화면에는 보유한 사용 가능 원소 전체를 표시하고, 캔버스에 실제로 사용 중인 서로 다른 원소 종류 수를 N개로 제한합니다.

**영향:** 과거 `UserElementStorageData`, 영업 시작 전 원소 선택 UI와 관련 규칙은 신규 구현 기준에서 제외합니다. 기존 원본 문서는 이력으로 보존합니다.

### D-002 세부 무기 종류 자동 판정

**결정:** 플레이어는 무기 대종류만 직접 선택합니다. 대검, 단검, 장창 등의 세부 종류는 스케치 분석 결과를 기반으로 시스템/AI가 자동 판정합니다.

### D-003 VLM 미사용

**결정:** 이미지나 Base64를 VLM에 직접 입력하지 않습니다.

```text
벡터 스트로크 → 래스터화 → OpenCV/수학 분석 → 구조화 JSON → 로컬 텍스트 LLM
```

### D-004 태그 시스템 MVP 핵심 포함

**결정:** 태그는 단순 생성 메타데이터가 아니라 MVP의 핵심 평가 시스템입니다. NPC 의뢰와 완성 무기에 모두 태그를 부여하고 태그 유사도를 평가 점수의 핵심 입력으로 사용합니다.

### D-005 마이그레이션 문서 상태

**결정:** 기존 Google Docs/Sheets에서 재구성한 문서는 검토 완료 전까지 `status: review`, `owner: TBD`로 관리합니다.

## 남은 미확정 정책

### 원소
- 한 제작에서 사용할 수 있는 최대 원소 종류 수 N과 증가 규칙
- 동일 원소 조합 허용 여부
- 조합 비용과 AI 신규 생성 제한
- 중복 원소 획득 처리
- AI 신규 원소 생성 최종 실패 처리
- 희귀 원소 획득 경로

### 태그
- 태그 유사도/거리 계산의 MVP 공식
- 중복 태그 1개당 가중치 증가 방식
- 반대 성질 태그의 감점 방식과 강도
- AI 태그 생성 출력 개수/범위
- 태그 명칭 정규화와 동의어 처리
- 태그 간 관계도 고도화 시점

### 무기 제작
- 브러시 굵기 범위
- 최대 원소 종류 수 N
- 주원소 자동 판정 가중치
- OpenCV 특징값 정규화 기준
- 단순화 윤곽선 핵심점 수
- 생성 품질 검증 기준
- 재시도 횟수와 타임아웃
- 결과 즉시 확정 정책의 장기 유지 여부

### 무기 모듈
- `CV_METRIC_WEIGHTS`
- 정량/의미 검색 Top K
- RRF 후보 수와 재정렬 Top K
- `MIN_FINAL_SCORE`
- 임베딩 모델
- 텍스트 인덱싱 실패 시 NumericOnly 정책
- 조립 보정 허용 범위

## 운영 규칙

결정 완료 시 항목을 삭제하지 않습니다. 관련 시스템 문서에 최종 정책을 반영하고 이 문서에는 결정 내용과 영향을 이력으로 유지합니다.
