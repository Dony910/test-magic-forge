# WBS

<Info>
  이 문서는 **Mintlify의 현행 PRD/GDD/시스템 문서**를 기준으로 관리합니다. 과거 Google Docs/Sheets 링크는 이력 확인용 메타데이터일 뿐, 신규 일정·범위 판단의 기준으로 사용하지 않습니다.
</Info>

## 1. 기준

- 기준 범위: **MVP 출시까지**
- 기준일: **2026-09-08**
- 제품 단계 기준: PRD의 `기획 → Tech PoC → 프로토타입 → 알파 → 베타 → MVP 런칭`
- 일정 단위: 큰 마일스톤 → 세부 마일스톤 → Plane 태스크
- 실행 관리: Plane
- 기획/정책 Source of Truth: Mintlify
- 목표일: 현재 MVP 출시일이 확정되지 않았으므로 **TBD**. 마일스톤 구조 승인 후 Plane에서 일정 산정

### 관리 원칙

- 큰 마일스톤은 **프로젝트가 도달해야 하는 결과 상태**를 정의합니다.
- 세부 마일스톤은 여러 작업이 함께 통과해야 하는 **Gate**로 사용합니다.
- 실제 구현/기획/콘텐츠 작업은 Plane 태스크로 관리합니다.
- `done`은 작업량이 아니라 **완료 기준을 검증했을 때만** 사용합니다.
- 시스템 상세 규칙은 WBS에 복제하지 않고 각 시스템 문서를 기준으로 합니다.

**완료 기준**

- M1.3에서 결정한 생성 아키텍처를 실제 제작 요청과 연결합니다.
- 결과에 최소 `완성 무기 결과, 세부 종류, 원소 반영 정보, Raw 태그 판정 가능 입력`이 포함됩니다.
- 실패 시 제작 입력을 유지하고 재시도할 수 있습니다.

#### M2.6 Evaluation & Result Prototype

**완료 기준**

- 완성 무기의 활성 태그 Raw 판정이 생성됩니다.
- 코드가 대표 WeaponTag를 선정합니다.
- RequestTag와 WeaponTag의 오차를 계산합니다.
- 결과를 플레이어에게 최소 피드백/보상 형태로 반환합니다.

#### M2.7 End-to-End First Playable

```text
NPC 방문/의뢰
→ 요구 해석
→ 제작 진입
→ 원소 스케치
→ 무기 생성
→ 태그 평가
→ 결과/보상
```

**완료 기준:** 위 흐름을 개발자 개입 없이 하나의 빌드에서 1회 이상 완주합니다.

#### M2.8 Core Loop Playtest Gate

PRD의 개발 최우선 목표인 **AI 무기 제작 코어 루프의 재미 검증**을 수행합니다.

검증 관점:

- NPC 요구 해석이 실제 선택으로 이어지는가
- 원소 선택과 스케치가 결과에 영향을 줬다고 느끼는가
- 생성 결과가 입력과 납득 가능하게 연결되는가
- AI 대기 시간이 반복 플레이를 방해하는가
- 평가 후 다음 제작을 개선하고 싶은 동기가 생기는가
