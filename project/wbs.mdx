<Info>
  이 문서는 **Mintlify의 현행 PRD/GDD/시스템 문서**를 기준으로 관리합니다. 실행 단위인 작업은 Plane에서만 관리하며, WBS는 기능(모듈) 수준까지만 기록합니다.
</Info>

## 1. 기준

- 기준 범위: **MVP 출시까지**
- 기준일: **2026-09-08**
- 제품 단계 기준: PRD의 `기획 → Tech PoC → 프로토타입 → 알파 → 베타 → MVP 런칭`
- 기획/정책 Source of Truth: Mintlify
- 실행 관리 Source of Truth: Plane

### 1.1 관리 계층

```text
메인 마일스톤
└─ 세부 마일스톤 = 프로젝트의 상태 = Plane Cycle
   └─ 기능(모듈) = 상태 달성을 위한 기능·활동 영역 = Plane Module
      └─ 작업 = 실제 실행 단위 = Plane Issue/Task
```

WBS는 **기능(모듈)까지** 관리합니다. 작업명, 담당자별 세부 실행 계획, 개별 이슈 상태와 일정은 WBS에 중복 기록하지 않고 Plane에서 관리합니다.

### 1.2 마일스톤과 기능의 구분

- 세부 마일스톤은 `리뷰`, `수정`, `조사`, `작성`, `구현` 같은 수행 행위가 아니라 **프로젝트가 도달한 상태**를 표현합니다.
- 기능(모듈)은 해당 상태를 만들기 위해 지속적으로 관리하는 기능 또는 활동 영역입니다.
- 하나의 기능 모듈은 여러 Cycle에서 계속 사용될 수 있습니다. Plane에서는 각 Task에 **Cycle과 Module을 함께 지정**해 현재 마일스톤과 기능 영역을 동시에 표현합니다.

## 4. 기능(모듈) — Plane Module

기능 모듈은 특정 Cycle 하나에서만 존재하는 일회성 작업이 아니라, 여러 세부 마일스톤에서 관련 Task를 묶는 **지속적인 책임 영역**으로 관리합니다.

| Module ID | Plane Module | 책임 범위 | 주요 관련 문서 |
| --- | --- | --- | --- |
| MOD-PRODUCT | 제품 기획 | PRD/GDD, MVP 범위, 핵심 경험과 제품 정책 | `/project/prd`, `/project/overview`, `/project/decisions` |
| MOD-DESIGN | 시스템 기획 | 시스템 간 책임·입출력·데이터 계약과 미확정 정책 관리 | 각 시스템 문서, `/project/decisions` |
| MOD-REQUEST | 의뢰·내러티브 | NPC 의뢰, 요구 전달, RequestTag 입력, 대화 및 의뢰 흐름 | 현재 전용 문서 추가 필요 |
| MOD-TAG | 태그 시스템 | TagDefinition, Raw WeaponTag 평가, 대표 태그 선정, 요구 태그 비교 기반 | `/systems/tags/overview` |
| MOD-ELEMENT | 원소 시스템 | 원소 데이터, ElementTagAffinity, 원소 조합과 AI 신규 원소 | `/systems/elements/overview`, `/systems/elements/spec` |
| MOD-WEAPON | 무기 시스템 | 무기 종류, 파츠 구조, 탐색·조립 정책과 무기 결과 구조 | `/systems/weapons/overview`, `/systems/weapons/module`, `/systems/weapons/content` |
| MOD-CRAFT | 무기 제작 | 제작 세션, 원소 팔레트, 스케치, 주원소, 제작 입력과 결과 확정 | `/systems/crafting/overview`, `/systems/crafting/spec` |
| MOD-SKETCH | 스케치 분석 | 벡터 입력, 래스터/마스크, OpenCV·수학 특징 추출과 구조화 입력 | `/systems/crafting/ai-pipeline` |
| MOD-AIGEN | AI 무기 생성 | 로컬 AI 무기 생성, 생성 결과 품질, 생성 방식 PoC와 Runtime 적용 | `/systems/crafting/ai-pipeline`, 무기/제작 문서 |
| MOD-EVALUATION | 평가·보상·후일담 | RequestTag/WeaponTag 평가 결과를 플레이 결과·보상·후일담에 연결 | 현재 전용 문서 추가 필요 |
| MOD-CONTENT | 게임 콘텐츠 | 태그·원소·무기·의뢰의 실제 콘텐츠 데이터 생산 및 운영 | 각 콘텐츠 문서 |
| MOD-NARRATIVE | 시나리오 콘텐츠 | NPC 대사, 의뢰 맥락, 후일담 콘텐츠 | 현재 전용 문서 추가 필요 |
| MOD-ART | 2D 아트/UI | MVP 플레이에 필요한 2D 아트와 UI 표현 자산 | 현재 전용 범위 문서 없음 |
| MOD-INTEGRATION | 게임 통합 | 시스템 간 연결과 Core Loop End-to-End 빌드 통합 | 관련 기능정의서 |
| MOD-PLAYTEST | 플레이테스트 | 핵심 재미, UX, 밸런스, AI 대기·결과 납득 가능성 검증 | `/project/prd`, 테스트 산출물 |
| MOD-RUNTIME | AI Runtime·호환성 | 로컬 모델 실행, GPU/VRAM, Unity 동시 실행, 패키징과 하드웨어 호환성 | Tech PoC 산출물 |
| MOD-RELEASE | 릴리즈 | MVP Scope Freeze, QA, Release Candidate와 배포 | 출시 단계 산출물 |

## 6. 크리티컬 의존성

```text
M0 기획 기준 확정
        ↓
M1 Tech PoC ─────────────┐
        ↓                │
        └──────────────→ M2 코어 프로토타입 / First Playable
                              ↓
                         M3 Alpha
                              ↓
                         M4 Beta
                              ↓
                         M5 MVP Launch
```

- M0에서 핵심 구조가 확정되지 않으면 관련 시스템 Module의 본 구현 Task가 Block됩니다.
- M1의 AI 생성/분석 기술 결정은 M2 제작 결과 구현의 선행 조건입니다.
- M2 First Playable과 핵심 재미 검증 결과는 M3 기능 범위와 우선순위 조정의 기준입니다.
- M3 Feature Complete 이후 신규 주요 기능은 기본적으로 Post-MVP 후보로 분리합니다.
- M4 Content Complete 이후에는 신규 콘텐츠 추가보다 품질 안정화를 우선합니다.
