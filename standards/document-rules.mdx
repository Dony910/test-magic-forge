# 문서 작성 공통 규칙

이 문서는 프로젝트 내 모든 기획 문서가 따라야 하는 공통 작성 규칙을 정의한다.

## 기본 원칙

- 모든 문서는 Markdown/MDX를 기준으로 작성한다.
- 문서 하나는 하나의 책임을 가진다.
- 결정된 내용과 미결정 내용을 명확히 구분한다.
- 구현 상태와 기획 확정 상태를 혼용하지 않는다.
- 중복 설명보다 원본 문서를 링크한다.
- 수치가 확정되지 않았다면 임의의 값을 만들지 않고 `TBD` 또는 `미정`으로 표시한다.
- 삭제보다 이력 보존을 우선한다.

## 상태 표기

- `확정`: 현재 기준으로 적용되는 기획
- `검토중`: 방향은 있으나 최종 결정 전
- `TBD`: 결정 필요
- `MVP 제외`: 현재 MVP 범위에 포함하지 않음
- `Deprecated`: 더 이상 신규 작업에 사용하지 않음

## 제목 규칙

- `#` 문서 제목은 Front Matter의 `title`과 동일한 의미를 가져야 한다.
- `##`는 주요 섹션, `###`는 하위 기능 단위에 사용한다.
- 4단계보다 깊은 헤딩은 가급적 사용하지 않는다.

## 표와 코드 블록

- 기능 목록, 파라미터, 데이터 필드는 Markdown 표를 우선 사용한다.
- JSON, YAML, C#, API 예시는 fenced code block을 사용한다.
- 표가 너무 커지면 기능정의서 또는 별도 데이터 문서로 분리한다.

## 변경 원칙

- 문서 구조를 크게 변경할 경우 `updated`와 `version`을 갱신한다.
- 의미가 변경된 결정은 `변경 이력`에 기록한다.
- 폐기된 문서는 삭제하지 않고 Deprecated 정책을 따른다.
