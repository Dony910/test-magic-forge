# 기능정의서 작성 가이드

`doc_type: feature`

기능정의서는 **개발자가 구현 가능한 기능 단위**로 동작, 입력, 출력, 상태, 예외와 구현 현황을 정의합니다. 게임 규칙의 근거는 시스템 기획서에서 가져오고, 이 문서는 구현 대상과 계약을 구체화합니다.

## 목차별 작성 가이드

| 목차 | 무엇을 작성하는가 | 간단한 예시 |
| --- | --- | --- |
| 1. 기능 개요 | 어떤 기능을 구현하는 문서인지, 대응하는 시스템 규칙을 요약합니다. | `무기 제작 화면에서 보유 원소를 브러시로 선택해 벡터 스케치를 작성한다.` |
| 2. 전제 조건 | 기능 실행 전에 충족되어야 하는 상태·데이터·권한을 적습니다. | `제작 세션이 Draft 상태이고 유저 보유 원소 목록이 로드되어 있어야 한다.` |
| 3. 기능 목록 | 구현 단위를 표로 나누고 기획 상태와 구현 상태를 분리합니다. | `원소 잠금 / 기획 확정 / 구현 완료` |
| 4. 상세 기능 | 각 기능의 목적, 입력, 처리 규칙, 출력, 상태 변화, 예외, 연동을 적습니다. | `사용 원소가 N종이면 미사용 원소 버튼을 disabled 처리한다.` |
| 5. 데이터/API 계약 | 클라이언트·서버·AI 사이에서 주고받는 필드와 스키마를 정의합니다. | `active_element_ids: string[]` |
| 6. 미확정 정책 | 구현을 막거나 분기시키는 미확정 정책을 적습니다. | `GENERATION_TIMEOUT TBD` |
| 7. 테스트 관점 | 정상, 경계값, 실패, 재시도 등 검증해야 하는 시나리오를 적습니다. | `N번째 원소 삭제 후 잠긴 원소가 다시 활성화되는지 확인` |
| 변경 이력 | 입력·출력·상태·예외 등 구현 계약 변경을 기록합니다. | `v0.2.0: 이미지 Base64 입력 제거` |

## 기능 목록 표 기준

```md
| 구분 | 주기능 | 상세기능 | 설명 | 기획 상태 | 구현 상태 | 담당 | 비고 |
|---|---|---|---|---|---|---|---|
| 클라이언트 | 원소 팔레트 | 원소 잠금 | 최대 사용 수 도달 시 미사용 원소 선택 차단 | 확정 | 완료 | TBD | |
```

- `기획 상태`: `확정`, `검토중`, `TBD`, `MVP 제외` 등 규칙의 결정 상태
- `구현 상태`: `미시작`, `구현 중`, `코드 리뷰중`, `완료`, `Blocked` 등 실제 개발 상태
- 구현 완료 여부가 기획 확정 여부를 대신하지 않습니다.

## 상세 기능 예시

```md
### 원소 잠금

#### 목적
동시에 사용할 수 있는 원소 종류 수를 제한한다.

#### 입력
- `active_element_ids`
- `max_element_count`

#### 처리 규칙
1. 서로 다른 실제 사용 원소 수를 계산한다.
2. `count >= max_element_count`이면 미사용 원소를 잠근다.
3. 사용 원소가 완전히 제거되면 다시 활성화한다.

#### 출력
- 잠금된 원소 목록
- 갱신된 팔레트 상태

#### 예외
현재 사용 중인 원소는 최대치 도달 후에도 잠그지 않는다.
```

## 최소 Markdown 골격

```md
# 기능정의서

## 1. 기능 개요
## 2. 전제 조건
## 3. 기능 목록
## 4. 상세 기능
## 5. 데이터/API 계약
## 6. 미확정 정책
## 7. 테스트 관점
## 변경 이력
```

## 기능정의서에 넣지 않는 내용

제품 목표나 게임 전체 핵심 재미를 다시 정의하지 않습니다. 정책 자체가 바뀌어야 한다면 먼저 시스템 기획서 또는 Decision에서 결정하고 기능정의서에 반영합니다.
