# WBS 작성 가이드

`doc_type: wbs`

WBS는 **프로젝트 수행을 작업 단위로 분해하고 일정, 담당, 의존성, 완료 기준을 관리하는 문서**입니다. 기획 내용을 설명하는 문서가 아니라 실행 계획을 관리하는 문서입니다.

## 목차별 작성 가이드

| 목차 | 무엇을 작성하는가 | 간단한 예시 |
| --- | --- | --- |
| 1. 기준 | WBS가 기준으로 삼는 범위, 마일스톤, 기준일, 일정 단위를 적습니다. | `기준 범위: MVP`, `기준일: 2026-08-24` |
| 2. 마일스톤 | 프로젝트의 큰 완료 지점과 완료 조건을 정의합니다. | `M1 프로토타입: 의뢰→제작→결과 흐름 플레이 가능` |
| 3. 작업 구조 | 실제 수행할 작업을 계층적으로 분해하고 담당·기간·상태·산출물을 적습니다. | `2.3 태그 시스템 / 평가 로직 정의 / 태그 시스템 기획서` |
| 4. 크리티컬 의존성 | 다른 작업의 시작·완료를 막는 핵심 선행 관계를 적습니다. | `태그 데이터 구조 확정 → 의뢰 평가 구현 가능` |
| 5. 리스크 | 일정 지연 가능성과 대응 방안을 적습니다. | `AI 생성 지연 성능 검증 실패 시 프로토타입 일정 영향` |
| 6. 변경 사항 | 일정, 범위, 담당 변경의 이유와 영향을 기록합니다. | `태그 시스템 MVP 승격으로 태스크 추가` |

## 마일스톤 표 예시

```md
| ID | 마일스톤 | 목표일 | 완료 기준 | 상태 |
|---|---|---|---|---|
| M1 | 코어 프로토타입 | TBD | 의뢰→제작→평가 1회 플레이 가능 | in-progress |
```

## 작업 구조 표 예시

```md
| WBS ID | 작업 | 산출물 | 담당 | 시작 | 종료 | 선행 작업 | 상태 | 완료 기준 |
|---|---|---|---|---|---|---|---|---|
| 2.1 | 태그 규칙 확정 | 태그 시스템 기획서 | TBD | TBD | TBD | - | review | 평가 규칙 승인 |
| 2.2 | 태그 평가 구현 | 기능정의/코드 | TBD | TBD | TBD | 2.1 | blocked | 테스트 통과 |
```

## 상태 권장값

- `todo`: 아직 착수하지 않음
- `in-progress`: 작업 중
- `blocked`: 선행 조건이나 문제로 진행 불가
- `review`: 산출물 검토 중
- `done`: 완료 기준 충족
- `dropped`: 범위에서 제외됨

## 완료 기준 작성 원칙

`구현 완료`, `기획 완료`처럼 모호하게 쓰지 않습니다. 실제로 확인 가능한 상태를 적습니다.

좋은 예:
- `PRD review 승인`
- `클라이언트에서 원소 3종 스케치 가능`
- `테스트 케이스 10개 통과`

나쁜 예:
- `거의 완료`
- `개발 끝`


## WBS에 넣지 않는 내용

기능의 상세 동작이나 게임 규칙은 링크만 남기고 시스템 기획서/기능정의서를 기준으로 합니다. WBS가 기획 원본이 되어서는 안 됩니다.
