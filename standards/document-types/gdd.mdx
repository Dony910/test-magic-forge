# GDD 작성 가이드

`doc_type: gdd`

GDD는 **게임이 어떤 경험과 규칙으로 작동하는지**를 정의하는 최상위 게임 디자인 문서입니다. PRD가 제품 목표를 다룬다면 GDD는 플레이어 경험과 전체 게임 구조를 다룹니다.

## 목차별 작성 가이드

| 목차 | 무엇을 작성하는가 | 간단한 예시 |
| --- | --- | --- |
| 1. 게임 개요 | 장르, 플레이 방식, 핵심 콘셉트와 한 줄 설명을 적습니다. | `AI 무기 제작을 중심으로 한 상점 경영 RPG` |
| 2. 플레이어 판타지 | 플레이어가 어떤 역할과 감정을 경험해야 하는지 적습니다. | `영웅의 운명을 무기로 바꾸는 대장장이이자 조력자` |
| 3. 핵심 재미 | 반복 플레이를 지탱하는 핵심 재미를 2~4개 축으로 정리합니다. | `의뢰 추론`, `원소 선택`, `스케치 창작`, `결과 확인` |
| 4. 게임 구조 | 화면·모드·Day 구조 등 게임의 큰 구조를 설명합니다. | `카운터 ↔ 공방`, `Day 단위 영업` |
| 5. 코어 루프 | 한 번의 핵심 플레이 사이클을 단계별로 적습니다. | `NPC 방문 → 제작 → 평가 → 보상` |
| 6. 메타 루프 | 여러 코어 루프가 누적되며 생기는 성장·수집·해금 구조를 적습니다. | `후일담 보상 → 신규 원소 → 제작 선택지 확장` |
| 7. 주요 시스템 지도 | 시스템 목록과 역할·연결 관계를 요약합니다. 세부 내용은 링크합니다. | `태그 → 의뢰/무기 평가`, `원소 → 제작`, `무기 시스템 → 생성 구조` |
| 8. 진행과 성장 | 플레이어가 장기적으로 무엇을 해금하고 성장시키는지 적습니다. | `상점 성장에 따라 최대 사용 원소 수 증가` |
| 9. 경제 구조 | 주요 재화의 획득·소비 방향을 개념 수준에서 정리합니다. | `골드 획득 → 공방 성장`, 상세 수치는 별도 밸런스 문서 |
| 10. 콘텐츠 구조 | NPC, 무기, 원소, 이벤트 등 콘텐츠가 어떤 단위로 공급되는지 적습니다. | `NPC 의뢰 + 후일담 세트`, `무기 대분류/소분류` |
| 11. UX 원칙 | 게임 경험을 지키기 위한 상위 UX 원칙을 적습니다. | `AI 대기 중에도 제작 흐름이 끊기지 않아야 한다.` |
| 12. 밸런스 원칙 | 세부 수치 대신 밸런싱 방향과 제약을 적습니다. | `정답 하나보다 여러 제작 해법을 허용한다.` |
| 13. MVP 범위 | GDD 관점에서 MVP에 포함되는 플레이 경험과 제외 경험을 적습니다. | 포함: `의뢰-제작-평가`; 제외: `랭킹` |
| 14. 시스템 간 의존성 | 어떤 시스템이 어떤 데이터·상태에 의존하는지 적습니다. | `평가 시스템은 의뢰 태그와 무기 태그에 의존` |
| 15. 결정 필요 항목 | 전체 게임 경험에 영향을 주는 미확정 사항을 적습니다. | `Day당 NPC 수 TBD` |
| 변경 이력 | 핵심 루프, 범위, 시스템 관계 변경을 기록합니다. | `v0.2.0: 태그 평가를 코어 루프에 포함` |

## 최소 Markdown 골격

```md
# GDD

## 1. 게임 개요
## 2. 플레이어 판타지
## 3. 핵심 재미
## 4. 게임 구조
## 5. 코어 루프
## 6. 메타 루프
## 7. 주요 시스템 지도
## 8. 진행과 성장
## 9. 경제 구조
## 10. 콘텐츠 구조
## 11. UX 원칙
## 12. 밸런스 원칙
## 13. MVP 범위
## 14. 시스템 간 의존성
## 15. 결정 필요 항목
## 변경 이력
```

## GDD에 넣지 않는 내용

특정 시스템의 세부 예외, 데이터 필드, API 계약, 전체 콘텐츠 행 목록은 각각 시스템 기획서·기능정의서·콘텐츠/Data 문서로 분리합니다.
