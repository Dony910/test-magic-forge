# PRD 작성 가이드

`doc_type: prd`

PRD는 **제품이 왜 존재하고 무엇을 검증해야 하는지**를 정의하는 최상위 제품 문서입니다. 게임 규칙의 세부 구현보다 사용자 가치, 목표, 범위와 성공 조건을 다룹니다.

## 언제 사용하는가

- 프로젝트 또는 큰 제품 단위의 방향을 정할 때
- MVP에서 무엇을 검증할지 합의할 때
- 기획·개발·아트가 같은 제품 목표를 바라보게 할 때

## 목차별 작성 가이드

| 목차 | 무엇을 작성하는가 | 간단한 예시 |
| --- | --- | --- |
| 1. 제품 개요 | 게임을 한두 문단으로 정의합니다. 장르, 핵심 사용자 행동, 차별점을 포함합니다. | `손님의 의뢰를 해석하고 AI로 맞춤 무기를 제작하는 상점 경영 게임` |
| 2. 문제와 기회 | 어떤 사용자 욕구나 시장 기회를 노리는지 적습니다. 해결책보다 문제를 먼저 씁니다. | `생성형 AI 결과를 감상하는 데서 끝나지 않고 직접 플레이하는 경험이 부족하다.` |
| 3. 목표 | 이번 제품/버전에서 달성해야 할 사용자·비즈니스 목표를 적습니다. | 사용자: `내 선택이 무기 결과에 반영됐다고 느낀다.` / 제품: `코어 루프 재미 검증` |
| 4. 타깃 사용자 | 핵심 사용자군, 플레이 성향, 기대 행동을 정의합니다. | `경영·크래프팅·스토리 게임을 선호하는 10대 후반~30대` |
| 5. 핵심 가치 제안 | 경쟁작이나 일반적인 경험과 비교해 이 게임이 주는 고유 가치를 한 문장씩 정리합니다. | `NPC 요구 추론 + 손그림 + AI 결과 생성이 하나의 루프로 연결된다.` |
| 6. 핵심 경험과 코어 루프 | 사용자가 반복하게 될 가장 중요한 경험의 순서를 적습니다. | `의뢰 수신 → 요구 추론 → 제작 → 전달 → 평가 → 후일담` |
| 7. MVP 범위 | 이번 검증에 반드시 필요한 것과 의도적으로 제외하는 것을 분리합니다. | 포함: `의뢰-제작-평가` / 제외: `거래, 랭킹, 고급 성장` |
| 8. 성공 지표 | 성공 여부를 판단할 지표와 관찰 기준을 적습니다. 수치가 없으면 `TBD`로 둡니다. | `제작 완료율`, `한 세션 평균 제작 횟수`, `FGT 재미 평가` |
| 9. 주요 리스크와 가설 | 제품이 실패할 수 있는 이유와 검증해야 할 가설을 적습니다. | `AI 대기 시간이 길면 제작 재미가 끊길 수 있다.` |
| 10. 로드맵 | 기능 목록이 아니라 제품 검증 단계와 각 단계의 목적을 적습니다. | `PoC → Prototype → Alpha → MVP` |
| 11. 결정 필요 항목 | 현재 제품 방향에 영향을 주지만 아직 확정하지 못한 사항을 모읍니다. | `AI 생성 비용 제한 정책 TBD` |
| 변경 이력 | 의미가 바뀐 결정, 범위 변경과 버전 변경을 기록합니다. | `v0.2.0: 태그 평가를 MVP 범위로 승격` |

## 최소 Markdown 골격

```md
# PRD

## 1. 제품 개요
## 2. 문제와 기회
## 3. 목표
### 3.1 사용자 목표
### 3.2 비즈니스/제품 목표
## 4. 타깃 사용자
## 5. 핵심 가치 제안
## 6. 핵심 경험과 코어 루프
## 7. MVP 범위
### 7.1 포함
### 7.2 제외
## 8. 성공 지표
## 9. 주요 리스크와 가설
## 10. 로드맵
## 11. 결정 필요 항목
## 변경 이력
```

## PRD에 넣지 않는 내용

- 함수, API, DB 필드 등 구현 상세
- 특정 시스템의 세부 규칙 전체
- 대량 콘텐츠 목록
- 작업 담당자별 일정표

이 내용들은 각각 기능정의서, 시스템 기획서, 콘텐츠/Data 문서, WBS로 분리합니다.
