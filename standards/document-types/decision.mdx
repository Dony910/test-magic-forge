# Decision 문서 작성 가이드

`doc_type: decision`

Decision 문서는 **중요한 선택과 그 근거를 이력으로 남기는 문서**입니다. 시스템 간 충돌, 기존 정책 변경, 여러 선택지 중 하나를 결정해야 할 때 사용합니다.

## 언제 사용하는가

- 둘 이상의 문서가 서로 다른 규칙을 말할 때
- 기존 `approved` 정책을 변경해야 할 때
- 나중에 “왜 이렇게 결정했는가”를 설명할 필요가 있을 때

## 목차별 작성 가이드

| 목차 | 무엇을 작성하는가 | 간단한 예시 |
| --- | --- | --- |
| 배경 | 왜 이 결정이 필요해졌는지 사실 위주로 설명합니다. | `원소 시스템 문서와 무기 제작 기능정의서의 사용 방식이 서로 다르다.` |
| 결정해야 하는 문제 | 선택해야 할 질문을 한 문장으로 명확히 적습니다. | `영업 전 원소 사전 보관을 유지할 것인가?` |
| 선택지 | 현실적인 대안을 나열하고 장단점을 간단히 적습니다. | A: 사전 보관 유지 / B: 전체 팔레트 + 실제 사용 N종 제한 |
| 결정 | 최종 선택을 단정적으로 기록합니다. | `B를 채택한다.` |
| 근거 | 왜 그 선택을 했는지 제품·게임·기술 관점의 근거를 적습니다. | `제작 전에 불필요한 선택 단계를 줄이고 현재 구현 방향과 일치한다.` |
| 영향받는 문서/시스템 | 수정해야 할 문서와 구현 영역을 링크합니다. | `원소 시스템`, `무기 제작`, `UserElementStorageData` |
| 후속 작업 | 결정 후 실제로 해야 할 수정·구현·Deprecated 작업을 적습니다. | `사전 보관 규칙 Deprecated`, `기능정의 갱신` |
| 변경 이력 | 결정 자체가 재검토되거나 후속 결정으로 대체될 때 기록합니다. | `v0.2.0: 후속 Decision D-014로 대체` |

## 작성 예시

```md
# 원소 사용 방식 결정

## 배경
원소 시스템 기획서는 영업 전 N종 사전 보관을 정의하지만 무기 제작 기능정의서는 전체 팔레트를 사용한다.

## 결정해야 하는 문제
제작에 사용할 원소를 영업 전에 미리 제한할 것인가?

## 선택지
- A. 영업 전 N종 사전 보관 유지
- B. 전체 보유 원소 표시 + 스케치 실제 사용 N종 제한

## 결정
B를 채택한다.

## 근거
- 제작 진입 전에 추가 선택 단계를 만들지 않는다.
- 스케치 중 선택의 자유를 유지한다.
- 현재 제작 구현 구조와 일치한다.

## 영향받는 문서/시스템
- 원소 시스템
- 무기 제작 시스템

## 후속 작업
- 사전 보관 규칙 Deprecated
- UserElementStorageData 신규 사용 중단
```

## Decision 작성 원칙

- 결정 전에는 `결정` 섹션을 `TBD`로 둘 수 있습니다.
- 결정 완료 후 Decision 문서는 삭제하지 않습니다.
- 실제 기준 규칙은 반드시 관련 PRD/GDD/시스템 문서에도 반영합니다.
- Decision 문서만 수정하고 기준 문서를 방치하지 않습니다.
