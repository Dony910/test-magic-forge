# 스케치 분석과 AI 파이프라인

현재 기술 방향은 **VLM 없이 로컬 텍스트 LLM을 사용하는 구조**입니다. 이미지 또는 이미지 Base64를 LLM에 직접 전달하지 않습니다.

## 전체 파이프라인

```text
벡터 스트로크 원본
→ 로컬 래스터화
→ 전체 실루엣/원소별 마스크 생성
→ OpenCV + 수학 특징 추출
→ 벡터 스트로크 요약
→ 구조화 JSON 압축
→ 로컬 텍스트 LLM 해석
→ 세부 무기 종류/파츠 후보/원소 영향 판정
→ 이미지 생성 및 메타데이터 생성
→ 스키마 검증
```

원본 벡터 좌표 전체도 LLM에 직접 보내지 않습니다. 토큰 비용이 크고 텍스트 모델의 수치 해석 부담이 높기 때문입니다.

## 전체 형태 특징

| 필드 | 의미 |
| --- | --- |
| `aspect_ratio_w_to_h` | 전체 가로/세로 비율 |
| `bounding_box` | 전체 영역 크기와 중심 |
| `center_of_mass` | 전체 무게 중심 |
| `left_right_area_ratio` | 좌우 면적 비율 |
| `top_bottom_area_ratio` | 상하 면적 비율 |
| `vertical_symmetry_score` | 세로축 대칭 점수 |
| `horizontal_symmetry_score` | 가로축 대칭 점수 |
| `linearity_score` | 전체 직선도 |
| `contour_count` | 주요 윤곽선 수 |
| `connected_component_count` | 분리된 주요 덩어리 수 |

## 원소별 영역 특징

각 원소는 최종 렌더링 상태를 기준으로 별도 마스크를 만들어 분석합니다.

- `element_id`
- `area_ratio`
- `center`
- `bounding_box`
- `left_right_area_ratio`
- `top_bottom_area_ratio`
- `connected_component_count`

## 스트로크 특징

- `stroke_count`
- `total_length`
- `average_brush_size`
- `direction_histogram`
- `intersection_count`
- `simplified_contour`

` simplified_contour`는 전체 좌표 대신 형태를 대표하는 정규화 핵심점만 전달합니다. 현재 16~64개가 제안되어 있으나 최종 값은 미확정입니다.

## AI 직접 입력 데이터

구조화 분석값 외에도 다음 정보를 전달합니다.

- 무기 대종류
- 실제 사용 원소 목록
- 원소별 최종 노출 비율
- 주원소 또는 주원소 미지정 상태
- 진행 중인 NPC 의뢰 정보
- 무기 시스템의 종류/파츠 정의
- 제작 시스템의 생성 규칙

## AI 출력

- 세부 무기 종류
- 파츠 구성 및 배치 정보
- 원소별 반영 정보
- 최종 주원소
- 무기 이름과 설명
- 속성 및 태그
- 생성 추적 ID

## 원칙

<Note>
  AI가 모든 것을 직접 추측하도록 두지 않고, 클라이언트에서 계산 가능한 형태 특징은 먼저 계산해 구조화합니다. LLM은 압축된 특징의 의미 해석과 분류·생성에 집중합니다.
</Note>
