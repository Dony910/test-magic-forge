# 무기 제작 시스템

## 1. 개요

플레이어가 무기 대종류를 선택하고 보유 원소를 물감처럼 사용해 스케치한 뒤, 로컬 형태 분석과 AI 생성 파이프라인을 통해 완성 무기를 만드는 핵심 제작 시스템입니다.

## 2. 목표

- 플레이어의 원소 선택과 스케치가 결과에 직접 반영되게 한다.
- 생성형 AI의 결과를 단순 감상이 아니라 조작 가능한 창작 경험으로 만든다.
- 제작 입력을 구조화해 로컬 모델의 부담과 토큰 사용량을 줄인다.
- 실패 시 입력을 보존해 재작업 비용을 줄인다.

## 3. 제작 흐름

```text
제작 진입
→ 무기 대종류 선택
→ 보유 원소 전체 팔레트 표시
→ 원소별 벡터 스케치
→ 주원소 지정(선택)
→ 입력 검증
→ 로컬 전처리 분석
→ 구조화 JSON 생성
→ 로컬 텍스트 LLM 분석/생성
→ 결과 검증
→ 태그 생성
→ 결과 확정
```

## 4. 핵심 규칙

### 4.1 무기 종류

- 플레이어는 **무기 대종류 하나만 선택**합니다.
- 세부 무기 종류는 스케치 분석 결과를 기반으로 시스템이 자동 판정합니다.

### 4.2 원소 팔레트

- 보유한 사용 가능 원소 전체를 표시합니다.
- **사전 원소 보관/선택 단계는 사용하지 않습니다.**
- 캔버스에 실제로 남아 있는 서로 다른 원소 종류 수를 실시간 계산합니다.
- 최대 N종에 도달하면 아직 사용하지 않은 원소를 잠급니다.
- 원소가 완전히 지워지면 사용 종류 수가 줄고 잠금이 해제됩니다.
- 최종 생성 입력에는 실제로 남아 있는 원소만 포함합니다.
- MVP에서 원소는 제작 시 소모하지 않습니다.

### 4.3 스케치

브러시, 지우개, 굵기 변경, Undo/Redo, 전체 지우기, 원소 전환, 확대/축소와 캔버스 이동을 지원합니다.

각 스트로크는 최소 다음 정보를 보관합니다.

- `stroke_id`
- `element_id`
- `points`
- `brush_size`
- `draw_order`
- `erase_data`

서로 다른 원소가 같은 위치에 겹치면 마지막으로 칠한 원소가 덮어씁니다. MVP에서 원소 혼합·시너지·상극은 적용하지 않습니다.

### 4.4 주원소

주원소는 완성 무기의 대표 속성과 디자인 방향에 가장 큰 영향을 주는 하나의 원소입니다.

- 실제 사용 원소 중 하나만 지정할 수 있습니다.
- 지정은 선택 사항입니다.
- 미지정 시 원소별 면적, 위치, 스트로크 비중 등을 기반으로 자동 판정합니다.

## 5. 입력 검증

제작 요청은 다음 조건을 만족해야 합니다.

- 실제 사용 원소가 1개 이상
- 무기 대종류 선택 완료
- 유효한 벡터 스트로크 존재
- 주원소 지정 시 실제 사용 원소에 포함

검증 실패 시 요청을 전송하지 않고 기존 입력을 유지합니다.

## 6. AI/분석 원칙

스케치 해석에는 VLM을 사용하지 않습니다. 상세 기술 흐름은 [스케치 분석과 AI 파이프라인](/systems/crafting/ai-pipeline)을 기준으로 합니다.

## 7. 출력

생성 성공 시 최소 다음 결과를 가집니다.

- 완성 무기 이미지/자산
- 세부 무기 종류
- 파츠 구성 및 배치 정보
- 사용 원소 및 주원소
- 무기 이름과 설명
- 속성
- **평가용 태그**
- 생성 추적 ID

## 8. 결과와 실패

MVP에서는 생성 성공 시 결과를 즉시 확정합니다. 여러 후보 비교와 생성 후 부분 수정은 제외합니다.

AI 응답 실패, 시간 초과, 필수값 누락, 결과 불일치 또는 유효성 검증 실패 시 기존 입력을 유지하고 재시도를 제공합니다.

## 9. 시스템 연동

- 원소 시스템: 제작 팔레트와 원소 메타데이터 제공
- 무기 시스템: 대/소분류와 파츠/조립 규칙 제공
- 태그 시스템: 완성 무기의 평가 태그 생성 및 의뢰 태그와 비교
- 의뢰 시스템: NPC 요구 정보 제공

## 10. MVP 제외

- 생성 후보 여러 개 비교
- 결과 재생성 선택 UI
- 생성 후 부분 수정
- 원소 시너지/상극/혼합
- 유저 수동 파츠 조립/조정

## 11. 확정 필요 항목

- 최대 실제 사용 원소 종류 수 N
- 브러시 굵기 범위
- 주원소 자동 판정 가중치
- 생성 재시도 제한
- 생성 타임아웃
- 결과 즉시 확정의 장기 정책
