# 무기 제작 기능정의

## 1. 기능 개요

무기 제작 진입부터 대종류 선택, 원소 팔레트, 벡터 스케치, 로컬 분석, AI 생성, 태그 생성, 결과 확정과 실패 재시도까지를 구현 단위로 정의합니다.

## 3. 상태 머신

```text
Draft → Validating → Generating → Success
                          └──────→ Failed
```

## 4. 입력 계약

제작 세션은 최소 다음 정보를 관리합니다.

```json
{
  "session_id": "string",
  "request_id": "string",
  "shop_level": 1,
  "max_element_count": null,
  "available_element_ids": [],
  "active_element_ids": [],
  "locked_element_ids": [],
  "primary_element_id": null,
  "weapon_category_id": null,
  "detected_weapon_type_id": null,
  "stroke_data": [],
  "shape_metrics": null,
  "element_regions": [],
  "stroke_metrics": null,
  "generation_status": "Draft",
  "generation_result": null
}
```

`max_element_count`의 실제 수치는 TBD이며 문서에서 임의로 1을 기본값으로 두지 않습니다.

## 5. 확정 정책

- 무기 대종류만 플레이어가 선택합니다.
- 세부 종류는 자동 판정합니다.
- 사전 원소 보관을 사용하지 않습니다.
- 원소 전체 팔레트에서 실제 사용 종류 수만 제한합니다.
- 최소 실제 사용 원소 수는 1개입니다.
- 주원소는 최대 1개이며 선택 사항입니다.
- 원소 겹침은 마지막 스트로크가 덮어씁니다.
- MVP에서 원소는 소모하지 않습니다.
- 이미지/Base64 VLM 입력은 사용하지 않습니다.
- 생성 결과에는 활성 태그 전체의 Raw 판정(`value 0~5`, `prominence 0~5`, `confidence 0~1`)과 코드에서 선정한 대표 WeaponTag가 포함됩니다.
- Raw 태그 판정은 보관하며 대표 태그에서 제외된 항목은 실제 의뢰 평가에서 0으로 취급합니다.
- 대표 태그 최대 개수는 하드코딩하지 않고 설정값으로 관리합니다.
- 생성 성공 시 결과를 즉시 확정합니다.

## 6. 출력 계약

- 세부 무기 종류
- 파츠 구성/배치
- 원소 반영 정보
- 주원소
- 이름/설명
- 속성
- Raw 태그 판정 목록(`tag_id`, `value`, `prominence`, `confidence`)
- 대표 WeaponTag 목록(`tag_id`, `value`)
- 생성 추적 ID

## 7. 예외

- 필수 입력 누락: 요청 전송 차단
- AI 응답 실패/타임아웃: Failed 전환 및 재시도 제공
- 필수 출력 누락: 검증 실패
- 무기 대종류 불일치: 결과 검증 실패
- 재시도 시 기존 분석값과 입력을 유지하고 새 추적 ID를 생성

## 8. 미확정 정책

- `MAX_SELECTABLE_ELEMENTS_BY_SHOP_LEVEL`
- `GENERATION_RETRY_LIMIT`
- `GENERATION_TIMEOUT`
- 주원소 자동 판정 가중치
- 분석 정규화 규칙
- 생성 품질 검증 기준
- 대표 WeaponTag 최대 종류 수의 정확한 MVP 값
- AI 태그 판정 검증 실패 시 재시도/최종 실패 정책
