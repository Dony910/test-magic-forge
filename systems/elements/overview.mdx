# 원소 시스템

## 1. 개요

원소는 고정된 이름이나 완성 무기의 태그가 아니라 조합에 참여하는 성질의 묶음입니다. 

각 원소는 최대 4개의 ElementTagAffinity를 가지며, 조합은 부모 성질을 보정·합산한 뒤 등록된 반응 규칙을 적용해 새로운 원소 성질을 만듭니다.

Element → ElementTagAffinity → 반응 규칙 평가 → 조합 결과 ElementTagAffinity → 제작 입력 힌트 → 완성 무기 평가 → WeaponTag

ElementTagAffinity는 완성 무기의 WeaponTag를 직접 확정하지 않습니다. 

Affinity는 제작 결과에서 특정 성질이 드러날 가능성을 나타내며, 실제 WeaponTag는 완성된 무기를 별도 평가해 결정합니다.

## 2. 기획 목표

- 원소마다 0~4개의 Affinity를 저장합니다.
- 실제 조합 입력 원소는 Affinity를 최소 1개 가집니다.
- 조합 결과는 부모의 단순 태그 합계가 아니라 등록된 반응 규칙으로 변모할 수 있습니다.
- 부모에게 없던 성질도 결과가 될 수 있으나, 반드시 등록된 TagDefinition과 반응 규칙을 통해서만 발생합니다.
- AI는 확정된 Affinity를 해석해 이름·설명·색상 등 표현만 만듭니다.

### MVP 제외

- 플레이어가 원소 투입량을 직접 지정하는 기능
- 조합당 복수 반응, 연쇄 반응, 상쇄 반응
- 전체 태그와 전체 반응표 콘텐츠의 확정
- 원소 시너지·상극의 전면 구현
- 스케치 위 실시간 원소 혼합

## 3. 핵심 개념

| 개념 | 정의 |
| --- | --- |
| TagDefinition | 전역 태그 사전. 태그는 상태·성질형 표현으로 관리합니다. |
| ElementTagAffinity | 원소가 가진 tag_id + strength(1~5) 성질 데이터입니다. |
| ElementReactionRule | 후보 성질 점수를 읽어 등록된 결과 태그로 변모시키는 규칙입니다. |
| WeaponTag | 완성 무기를 평가한 뒤 결정되는 별도 결과입니다. |
| 조합 키 | 순서와 무관하게 같은 조합 결과를 재사용하기 위한 검색 키입니다. |

반응으로 생긴 성질도 별도 데이터 타입이 아닙니다. 

모든 결과 성질은 ElementTagAffinity로 저장되고 다음 조합에 다시 참여합니다.

## 4. 제작에서의 사용 규칙

- 제작 화면에는 플레이어가 보유한 사용 가능 원소 전체를 표시합니다.
- 영업 시작 전 사용할 원소를 미리 보관·선택하는 단계는 사용하지 않습니다.
- 한 제작에서 실제 사용할 수 있는 서로 다른 원소 종류는 최대 N개입니다.
- MVP에서는 제작에 사용한 원소를 소모하지 않습니다.
- 같은 위치에 원소가 겹치면 마지막으로 칠한 원소가 덮어씁니다. 제작 캔버스 위 실시간 혼합·시너지·상극은 MVP에서 적용하지 않습니다.

## 5. 원소 성향과 태그 친화도

Element: element_id, name, affinities

ElementTagAffinity: tag_id는 TagDefinition ID, strength는 int 1~5

- 원소 하나에는 같은 tag_id를 중복 저장할 수 없습니다.
- tag_id는 존재하고 활성화된 TagDefinition을 참조해야 합니다.
- strength는 플레이어 투입량이 아니라 원소 안에서 해당 성질의 상대적 강도입니다.
- 원소는 0~4개의 Affinity를 저장할 수 있지만 실제 조합 입력 원소는 최소 1개를 가져야 합니다.

| 내부 값 | UI 표시 |
| --- | --- |
| 1~2 | 약함 |
| 3 | 보통 |
| 4~5 | 강함 |

## 6. 원소 조합

MVP의 조합 입력 수는 2개이며 순서 비의존 방식입니다.

원소 A + 원소 B 선택 → 입력 검증 → 부모 Affinity 보정·병합 → 반응 규칙 평가 → 최종 Affinity 선정 → combination_key 생성·기존 결과 조회 → 있으면 저장 결과 반환 → 없으면 표현 정보 생성·검증 → 원소와 조합식 저장 → 유저 보유 목록 추가

두 부모 원소는 MVP에서 동등한 비중으로 조합합니다. 

각 부모의 Affinity 강도 총합을 비교하고, 총합이 작은 부모의 점수를 큰 부모 총합에 맞춰 비례 보정한 뒤 같은 tag_id의 후보 점수를 합산합니다.

S_A = 부모 A의 Affinity strength 총합 S_B = 부모 B의 Affinity strength 총합 T = max(S_A, S_B) 보정 점수(element, tag) = strength(tag) × T / S_element 기본 후보 점수(tag) = 두 부모의 보정 점수 합

반응 규칙 적용과 후보 선정은 소수점 후보 점수로 처리합니다. 선택된 최종 태그만 비율 기반 반올림으로 정수 강도 1~5에 저장합니다.

## 7. 반응 규칙과 반응표

반응 조건은 별도 조합 태그가 아니라 ElementReactionRule의 all/any 조건으로 표현합니다. 규칙이 통과하면 원본 태그 후보 점수는 결과 태그 후보 점수로 이전됩니다. 결과 태그가 이미 후보에 있으면 점수를 합산합니다.

ElementReactionRule: rule_id, priority, transformation_mode, conditions, effects, score_multiplier, enabled, rule_version

AI나 런타임은 태그를 자유롭게 발명·등록·수정할 수 없습니다.

반응표의 가로 태그는 작용 태그, 세로 태그는 피작용 태그입니다. 이는 플레이어가 고르는 조합 순서가 아니라 규칙상 역할을 뜻합니다.

| 기호 | 의미 |
| --- | --- |
| ○ | 가로 태그인 실행자만 변모합니다. |
| △ | 세로 태그인 피실행자만 변모합니다. |
| □ | 양쪽 태그가 모두 변모합니다. |
| × | 반응하지 않으며 기본 합성 결과를 유지합니다. |

예: 뜨거움 + 단단함은 △ 규칙 후보이며, 조건을 만족하면 단단함 → 물러짐으로 변모합니다.

### MVP 실행 순서

1. 부모 Affinity를 보정하고 같은 태그 후보 점수를 합산합니다.
2. 통과한 반응 규칙 중 priority가 가장 높은 한 개를 적용합니다. 동률이면 rule_id 오름차순을 사용합니다.
3. 규칙의 원본 태그 후보 점수를 결과 태그 후보 점수로 이전·합산합니다.
4. 단일 변모 결과는 상위 6개 후보 안이면 보호합니다. 양쪽 변모 결과는 각 결과 태그가 각각 상위 5개 후보 안이면 보호합니다.
5. 보호 결과를 최종 4칸에 강제 포함하고 일반 후보 중 낮은 순위를 밀어냅니다.
6. 나머지 슬롯은 후보 점수순으로 채운 뒤 1~5 강도로 환산합니다.

동점 순서: 보호 여부 → 후보 점수 내림차순 → 반응 결과 여부 → tag_id 오름차순

## 8. AI 신규 원소 생성

### 입력

- 부모 원소의 이름·설명·색상과 ElementTagAffinity
- 규칙 엔진이 확정한 최종 Affinity
- 적용된 반응 규칙 ID와 사람이 읽을 수 있는 반응 요약
- 세계관 톤과 출력 JSON 스키마

### AI의 역할과 검증

AI는 확정된 Affinity를 바탕으로 이름·설명·색상 등 표현만 생성합니다. AI는 Affinity를 변경하거나 새 태그를 제안할 수 없습니다.

- name: 필수, 최대 12자
- description: 필수, 최대 길이 정책은 TBD
- color_hex: 유효한 HEX 형식
- tag_affinities: 서버 규칙 엔진이 확정한 값만 저장
- 중복 원소명, 금칙어, 세계관 톤을 검증

## 9. 다른 시스템과의 연동

- 무기 제작·생성 시스템은 실제 사용 원소의 Affinity를 제작 입력 힌트로 사용합니다.
- 원소의 Affinity는 무기 태그를 직접 결정하지 않으며, 완성 무기는 별도의 평가로 WeaponTag를 결정합니다.
- 태그 사전, Affinity 값, 반응 규칙 데이터는 태그 시스템 및 반응 규칙 시트가 관리합니다.
- 조합 결과에는 부모 원소 ID, 부모 Affinity 버전, 적용 규칙 버전, 최종 Affinity를 저장합니다.
- 같은 정렬 부모 원소, Affinity 분포, 부모 Affinity 버전, 규칙 버전은 같은 combination_key로 재사용합니다.
- 부모 Affinity, 반응 규칙, 태그 사전이 바뀌면 관련 조합 결과를 stale 상태로 표시하고 재생성 정책을 적용합니다.

## 10. Deprecated 규칙

- 부모 Affinity의 단순 union만으로 조합 결과를 확정하는 규칙
- 반응 조건을 별도 Affinity로 저장하는 규칙
- AI가 부모에게 없는 태그를 자유롭게 발명해 저장하는 규칙
- ElementTagAffinity를 완성 무기의 WeaponTag와 동일시하는 규칙
- 조합 입력 순서가 작용·피작용 방향을 결정하는 규칙
- 플레이어가 원소마다 1~5 투입량을 직접 선택하는 규칙
- 과거의 당일 원소 사전 보관 및 영업 시작 전 선택·잠금 정책

## 11. MVP 제외

- 원소 도감, 최초 발견자, 거래, 숙련도, 랭킹
- 전체 원소 콘텐츠와 전체 반응 시트 입력
- 원소 시너지·상극의 전면 구현
- 원소 조합 AI 프롬프트의 최종 튜닝
- 스케치 위 실시간 원소 혼합
- 2D/3D 태그 공간의 런타임 연동

## 12. 확정 필요 항목

- □ 규칙에서 두 원본 태그가 하나의 결과 태그로 합쳐질 때 상위 5개 기준을 적용하는지 여부
- 한 반응 규칙이 만들 수 있는 서로 다른 결과 태그 수 제한
- 한 후보가 나머지 후보 점수 합계 이상일 때 1위로 먼저 고정하고, 남은 후보로 2~4위를 선정하는 압도적 1위 분리 정책
- 태그 표시명의 최종 표기 규칙: 상태·성질형 표현을 기본으로 하되 실제 태그 사전 리뷰에서 확정
- 최대 동시 사용 원소 종류 수 N 및 증가 규칙
- 동일 원소 조합 허용 여부, 조합 비용, AI 신규 생성 제한, 중복 획득 처리, 최종 AI 실패 처리, 희귀 원소 획득 구조
