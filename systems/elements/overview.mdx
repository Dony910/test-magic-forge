# 원소 시스템

## 1. 개요

원소는 무기 제작에 사용하는 핵심 재료이자 생성 결과의 색상, 성질, 설명과 디자인 무드에 영향을 주는 게임 내부 입력 단위입니다.

## 2. 기획 목표

- 생성형 AI 입력을 게임 규칙 안에서 통제 가능한 재료 단위로 제공한다.
- 의뢰를 해석한 플레이어가 적절한 원소를 선택하도록 만든다.
- 두 원소의 조합을 통해 새로운 원소를 발견하는 실험과 수집의 재미를 제공한다.
- 동일 조합은 동일 결과를 반환해 결과 일관성과 공유 가능성을 확보한다.

## 3. 핵심 개념

| 개념 | 정의 |
| --- | --- |
| 원소 | 무기 제작에 사용하는 재료. 이름, 설명, 색상 정보를 가진다. |
| 기본 원소 | 초기 진행에서 제공되는 기초 원소 |
| 조합 원소 | 두 원소를 조합해 생성된 원소 |
| 희귀 원소 | 후일담, 이벤트 등 특수 경로를 통해 획득하는 확장 원소 |
| 조합 키 | 두 원소 ID를 정렬해 생성하는 순서 비의존 검색 키 |

## 4. 제작에서의 사용 규칙

- 제작 화면에는 플레이어가 보유한 사용 가능 원소 전체를 표시합니다.
- **영업 시작 전 사용할 원소를 미리 보관/선택하는 단계는 사용하지 않습니다.**
- 한 제작에서 실제 사용할 수 있는 서로 다른 원소 종류는 최대 N개입니다.
- N개가 사용 중이면 아직 사용되지 않은 다른 원소는 잠깁니다.
- 특정 원소가 캔버스에서 완전히 제거되면 사용 중 원소 종류 수가 감소하고 다른 원소를 사용할 수 있습니다.
- MVP에서는 제작에 사용한 원소를 소모하지 않습니다.
- 같은 위치에 원소가 겹치면 마지막으로 칠한 원소가 덮어씁니다. MVP에서는 원소 혼합·시너지·상극을 적용하지 않습니다.

## 5. 원소 조합

MVP의 조합 입력 수는 **2개**이며 순서 비의존 방식입니다.

```text
원소 A + 원소 B 선택
→ 입력 검증
→ combination_key 생성
→ 기존 조합 조회
→ 있으면 저장 결과 반환
→ 없으면 AI 신규 생성
→ 응답 검증
→ 원소/조합식 저장
→ 유저 보유 목록 추가
```

## 6. 원소 성향과 태그 친화도

원소는 완성 무기 태그를 직접 보유하는 대신, 특정 무기 성질을 발현시키기 쉬운 정도인 `ElementTagAffinity`를 가집니다.

- 원소당 최대 Affinity는 4개입니다.
- 값은 `1~5`이며 `1`도 허용합니다.
- 기본 원소 및 운영자 등록 원소는 기획자가 직접 설정합니다.
- 조합으로 처음 생성되는 신규 원소는 AI가 활성 태그 목록에서 Affinity를 생성합니다.
- AI가 생성한 Affinity는 원소 데이터와 함께 저장되며 이후 운영자가 수정할 수 있습니다.
- 입력 원소의 Affinity를 단순 합산/평균해 결과 Affinity를 만들지 않습니다. 신규 원소의 실제 설명과 물성을 기준으로 다시 선정합니다.
- 결과 Affinity는 부모 원소 Affinity의 합집합으로 제한하지 않습니다. 조합으로 새롭게 발생한 물성·현상에 근거가 있다면 부모에게 없던 활성 태그도 새 Affinity로 선택할 수 있습니다.

플레이어에게는 태그명과 함께 수치 구간을 성향 강약으로 보여줍니다.

| 내부 값 | UI 표시 |
| --: | --- |
| 1~2 | 약함 |
| 3 | 보통 |
| 4~5 | 강함 |

동일한 계열의 원소라도 Affinity 구성을 다르게 하여 선택의 차이를 만듭니다. 상세 규칙은 [태그 시스템](/systems/tags/overview)을 기준으로 합니다.

## 7. AI 신규 원소 생성

### 입력

- 원소 A/B 이름
- 원소 A/B 설명
- 원소 A/B 색상
- 원소 A/B `ElementTagAffinity`
- 활성 태그 목록 및 판정 가이드
- 세계관 톤
- 출력 JSON 스키마

### 필수 출력

```json
{
  "name": "화염강",
  "description": "불꽃의 열기가 강철 내부에 스며든 붉은 금속 원소",
  "color_hex": "#D94A2B",
  "tag_affinities": [
    { "tag_id": "hard", "value": 5 },
    { "tag_id": "hot", "value": 4 },
    { "tag_id": "sturdy", "value": 4 },
    { "tag_id": "glowing", "value": 2 }
  ]
}
```

### 검증

- `name`: 필수, 최대 12자
- `description`: 필수, 최대 길이 정책은 TBD
- `color_hex`: 유효한 HEX 형식
- `tag_affinities`: 활성 태그만 허용, 최대 4개, 값 `1~5`, 중복 `tag_id` 금지
- 중복 원소명 검증
- 금칙어/세계관 톤 검증

신규 생성 원소와 Affinity는 조합식과 함께 DB에 저장합니다. 동일한 순서 비의존 조합은 이후 AI를 다시 호출하지 않고 저장된 결과를 재사용합니다.

## 8. 다른 시스템과의 연동

- 무기 제작 시스템은 보유 원소와 원소별 공개 성향을 팔레트/제작 컨텍스트에 사용합니다.
- 원소의 Affinity는 무기 태그를 직접 결정하지 않으며, 완성 무기는 별도의 AI 태그 판정을 거칩니다.
- 태그 사전, Affinity 값, AI 신규 원소 태그 규칙은 [태그 시스템](/systems/tags/overview)이 담당합니다.

## 9. Deprecated 규칙

과거 원소 기획서의 **당일 원소 사전 보관 시스템**은 2026-08-24 결정으로 폐기되었습니다. `UserElementStorageData`, 영업 시작 전 원소 선택/잠금 정책은 신규 구현 기준으로 사용하지 않습니다. 기존 Google Docs/Sheets 원본은 이력 확인을 위해 보존합니다.

## 10. MVP 제외

- 원소 도감
- 최초 발견자
- 거래
- 숙련도
- 랭킹
- 원소 시너지·상극·혼합

## 11. 확정 필요 항목

- 최대 동시 사용 원소 종류 수 N 및 증가 규칙
- 동일 원소 조합 허용 여부
- 조합 비용
- AI 신규 생성 제한
- 중복 획득 처리
- 최종 AI 실패 처리
- 희귀 원소 획득 구조
