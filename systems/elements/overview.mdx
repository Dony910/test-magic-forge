# 원소 시스템

## 1. 개요

원소는 무기 제작에 사용하는 핵심 재료이자 생성 결과의 색상, 성질, 설명과 디자인 무드에 영향을 주는 게임 내부 입력 단위입니다.

## 2. 기획 목표

- 생성형 AI 입력을 게임 규칙 안에서 통제 가능한 재료 단위로 제공한다.
- 의뢰를 해석한 플레이어가 적절한 원소를 선택하도록 만든다.
- 두 원소의 조합을 통해 새로운 원소를 발견하는 실험과 수집의 재미를 제공한다.
- 동일 조합은 동일 결과를 반환해 결과 일관성과 공유 가능성을 확보한다.

## 3. 핵심 개념

| 개념 | 정의 |
| --- | --- |
| 원소 | 무기 제작에 사용하는 재료. 이름, 설명, 색상 정보를 가진다. |
| 기본 원소 | 초기 진행에서 제공되는 기초 원소 |
| 조합 원소 | 두 원소를 조합해 생성된 원소 |
| 희귀 원소 | 후일담, 이벤트 등 특수 경로를 통해 획득하는 확장 원소 |
| 조합 키 | 두 원소 ID를 정렬해 생성하는 순서 비의존 검색 키 |

## 4. 제작에서의 사용 규칙

- 제작 화면에는 플레이어가 보유한 사용 가능 원소 전체를 표시합니다.
- **영업 시작 전 사용할 원소를 미리 보관/선택하는 단계는 사용하지 않습니다.**
- 한 제작에서 실제 사용할 수 있는 서로 다른 원소 종류는 최대 N개입니다.
- N개가 사용 중이면 아직 사용되지 않은 다른 원소는 잠깁니다.
- 특정 원소가 캔버스에서 완전히 제거되면 사용 중 원소 종류 수가 감소하고 다른 원소를 사용할 수 있습니다.
- MVP에서는 제작에 사용한 원소를 소모하지 않습니다.
- 같은 위치에 원소가 겹치면 마지막으로 칠한 원소가 덮어씁니다. MVP에서는 원소 혼합·시너지·상극을 적용하지 않습니다.

## 5. 원소 조합

MVP의 조합 입력 수는 **2개**이며 순서 비의존 방식입니다.

```text
원소 A + 원소 B 선택
→ 입력 검증
→ combination_key 생성
→ 기존 조합 조회
→ 있으면 저장 결과 반환
→ 없으면 AI 신규 생성
→ 응답 검증
→ 원소/조합식 저장
→ 유저 보유 목록 추가
```

## 6. AI 신규 원소 생성

### 입력

- 원소 A/B 이름
- 원소 A/B 설명
- 원소 A/B 색상
- 세계관 톤
- 출력 JSON 스키마

### 필수 출력

```json
{
  "name": "화염강",
  "description": "불꽃의 열기가 강철 내부에 스며든 붉은 금속 원소",
  "color_hex": "#D94A2B"
}
```

### 검증

- `name`: 필수, 최대 12자
- `description`: 필수, 최대 길이 정책은 TBD
- `color_hex`: 유효한 HEX 형식
- 중복 원소명 검증
- 금칙어/세계관 톤 검증

## 7. 다른 시스템과의 연동

- 무기 제작 시스템은 보유 원소를 팔레트에 제공합니다.
- 원소 정보는 무기 생성의 색상·효과·설명·태그 생성에 영향을 줄 수 있습니다.
- 태그 기반 의뢰 평가는 [태그 시스템](/systems/tags/overview)이 담당합니다.

## 8. Deprecated 규칙

과거 원소 기획서의 **당일 원소 사전 보관 시스템**은 2026-08-24 결정으로 폐기되었습니다. `UserElementStorageData`, 영업 시작 전 원소 선택/잠금 정책은 신규 구현 기준으로 사용하지 않습니다. 기존 Google Docs/Sheets 원본은 이력 확인을 위해 보존합니다.

## 9. MVP 제외

- 원소 도감
- 최초 발견자
- 거래
- 숙련도
- 랭킹
- 원소 시너지·상극·혼합

## 10. 확정 필요 항목

- 최대 동시 사용 원소 종류 수 N 및 증가 규칙
- 동일 원소 조합 허용 여부
- 조합 비용
- AI 신규 생성 제한
- 중복 획득 처리
- 최종 AI 실패 처리
- 희귀 원소 획득 구조
