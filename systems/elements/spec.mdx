# 원소 기능정의 및 데이터

## 구현 상태 요약

최신 기능정의서를 기준으로 원소 보관 UI와 원소 조합의 주요 클라이언트 기능은 대부분 구현 완료 상태입니다. 서버 검증과 일부 정책은 구현 중이거나 추가 결정이 필요합니다.

| 영역 | 상태 요약 |
| --- | --- |
| 원소 보관 화면/선택/표시 | 구현 완료 |
| 보유 및 상태 검증 | 구현 중 또는 완료 |
| 당일 보관 데이터 저장/잠금 | 구현 완료 |
| 원소 조합 UI | 구현 완료 |
| 조합 입력 검증/키 생성/DB 조회 | 구현 완료 |
| AI 신규 원소 생성 | 구현 완료 |
| 신규 원소 검증 | 대부분 구현 완료, 일부 정책 검토 중 |
| 조합 결과 연출 | 구현 중 |
| 비용·제한·중복 정책 | 미시작 또는 미확정 |

## 주요 데이터 구조

### ElementData

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `element_id` | INT / UUID | 원소 고유 ID |
| `element_name` | STRING | 고유 원소명 |
| `description` | STRING | 원소 설명 |
| `primary_color_hex` | STRING | 주색 |
| `secondary_color_hex` | STRING | 보조색 |
| `accent_color_hex` | STRING | 강조색 |
| `source_type` | ENUM | 기본 / 조합 / 보상 / 운영자 등록 |
| `is_ai_generated` | BOOL | AI 생성 여부 |
| `status` | ENUM | 사용 가능 / 검수 필요 / 비활성 |

### ElementRecipeData

| 필드 | 설명 |
| --- | --- |
| `recipe_id` | 조합 레시피 ID |
| `combination_key` | 정렬된 입력 원소 ID 기반 UNIQUE 키 |
| `element_a_id` | 입력 원소 A |
| `element_b_id` | 입력 원소 B |
| `result_element_id` | 결과 원소 |
| `generation_type` | DB / AI / 운영자 등록 |
| `status` | 사용 가능 / 검수 필요 / 차단 |

### UserElementData

유저가 어떤 원소를 언제 어떤 방식으로 획득했는지 관리합니다. `user_id`, `element_id`, `acquired_at`, `acquire_type`, `use_count`, `favorite` 등을 포함합니다.

### UserElementStorageData

과거 원소 기획서의 당일 보관 시스템용 데이터입니다. `user_id`, `day_id`, `selected_element_ids`, `max_storage_count`, `locked` 등을 포함합니다. 이 구조를 최종 플레이 규칙에 유지할지는 결정이 필요합니다.

## 주요 파라미터

| 파라미터 | 현재 값 | 상태 |
| --- | --: | --- |
| `ELEMENT_COMBINE_INPUT_COUNT` | 2 | 확정 |
| `ELEMENT_NAME_MAX_LENGTH` | 12 | 확정 |
| `ELEMENT_DESC_MAX_LENGTH` | 120 제안 | 추후 확정 |
| `MAX_DAILY_ELEMENT_STORAGE` | N | 추후 확정 |
| `AI_GENERATION_DAILY_LIMIT` | 미정 | 추후 확정 |
| `AI_RETRY_COUNT` | 1 제안 | 추후 확정 |
| `ELEMENT_COMBINE_COST_GOLD` | 미정 | 추후 확정 |

## 예외 처리

- AI 응답 실패: 재시도 후 최종 실패 정책 적용
- 중복 이름: 기존 DB와 충돌 여부 검증
- 잘못된 HEX: 응답 검증 실패
- 미보유/비활성 원소: 요청 거부
- 최대 선택 수 초과: 클라이언트에서 차단 및 안내

미확정 정책은 [결정 필요 항목](/project/decisions)에서 통합 관리합니다.
