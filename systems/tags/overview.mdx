# 태그 시스템

## 1. 개요

태그 시스템은 NPC 의뢰와 완성 무기의 내부 의미를 비교 가능한 데이터로 표현하고, 두 데이터가 얼마나 유사한지 평가하는 MVP 핵심 시스템입니다.

태그의 **표시 명칭은 형용사로 고정**합니다. 예: `가벼운`, `날카로운`, `조용한`, `화려한`.

## 2. 기획 목표

- NPC의 자연어 요구를 게임 내부에서 비교 가능한 값으로 변환한다.
- AI가 생성한 무기의 성격을 동일한 표현 체계로 기록한다.
- 의뢰와 무기의 유사도가 높을수록 높은 평가 점수를 주도록 한다.
- 단순 정답/오답이 아니라 여러 성질의 조합으로 제작 결과를 평가한다.

## 3. 핵심 규칙

### 3.1 다중 태그

하나의 의뢰와 하나의 무기는 여러 태그를 동시에 가질 수 있습니다.

```text
의뢰: [가벼운, 조용한, 날카로운]
무기: [가벼운, 가벼운, 날카로운, 어두운]
```

### 3.2 중복 태그

동일 태그가 여러 번 존재할 수 있습니다. 중복은 해당 성질의 **강도/비중**을 표현하는 데이터로 사용합니다.

중복 1개당 실제 평가 가중치가 선형 증가할지, 감쇠 곡선을 적용할지는 TBD입니다.

### 3.3 평가 방향

- 요구 태그와 무기 태그가 유사할수록 점수가 올라갑니다.
- 요구와 반대되는 성질은 감점에 사용할 수 있습니다.
- 단순 문자열 일치만이 아니라 AI/임베딩 또는 정규화된 의미 비교를 사용할 수 있습니다.
- MVP의 구체 유사도 계산 공식은 TBD입니다.

## 4. 태그 생성

### 의뢰 태그

NPC 대화/의뢰 정보에서 AI가 요구 태그를 생성합니다. 플레이어에게 내부 태그를 그대로 노출할 필요는 없습니다.

### 무기 태그

완성 무기의 원소, 형태, 세부 무기 종류, 설명과 생성 결과를 바탕으로 AI가 무기 태그를 생성합니다.

## 5. 데이터 개념 모델

```text
Tag
- tag_id
- adjective
- normalized_key
- status

TaggedValue
- target_type: request | weapon
- target_id
- tag_id
- count
```

실제 DB 구조와 `count` 저장 방식은 기능정의 단계에서 확정합니다.

## 6. 평가 흐름

```text
NPC 대화
→ 요구 태그 생성
→ 플레이어 제작
→ 완성 무기 태그 생성
→ 태그 집합 비교
→ 유사도 점수 + 반대 성질 감점
→ 최종 평가
→ 보상/후일담 입력
```

## 7. 다른 시스템과의 연동

- 의뢰/내러티브 시스템: 요구 태그 생성 입력 제공
- 무기 제작 시스템: 완성 무기 태그 생성 입력 제공
- 평가 시스템: 태그 유사도 결과를 점수로 사용
- 후일담 시스템: 최종 평가 결과를 분기 입력으로 사용할 수 있음

## 8. 고도화 범위

태그 간 관계도, 동의어/유의어 그래프, 상극 관계, 의미 거리 캐싱 등은 MVP 이후 고도화 요소로 둡니다. 단, MVP에서도 반대 성질에 대한 기본 감점은 필요할 수 있습니다.

## 9. 확정 필요 항목

- 태그 유사도 계산 방식
- 중복 태그 가중치 함수
- 반대 태그 정의 및 감점 강도
- 한 의뢰/무기에 생성할 태그 최대 개수
- 형용사 정규화 및 동의어 처리
- AI 출력 스키마
- 평가 점수 정규화 범위
