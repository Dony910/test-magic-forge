# 무기 모듈 파이프라인

이 문서는 최신 **무기 모듈 시스템 기능정의서**를 기준으로 파츠 분석, 검색과 자동 조립 구조를 정리합니다.

## 1. 파츠 분석

현재 MVP에서는 파츠별 스케치 입력을 수집하고, 무기 제작 시스템과 동일한 공통 분석 모듈을 각 파츠에 독립적으로 적용합니다.

```text
파츠 벡터 스트로크
→ 로컬 래스터화
→ 실루엣/원소별 마스크
→ OpenCV + 수학 분석
→ cv_metrics 정규화
→ 로컬 텍스트 LLM 설명 생성
→ 검증
→ 수치 인덱스 + 텍스트 인덱스 등록
```

### 정량 특징

- 가로·세로 비율
- 바운딩 박스
- 무게 중심
- 좌우/상하 면적 분포
- 세로/가로 대칭도
- 직선도
- 윤곽선 수
- 연결 영역 수
- 원소별 영역 비율과 위치
- 스트로크 수, 길이, 평균 굵기, 방향 비중, 교차 수
- 단순화 윤곽선

### 자연어 특징

로컬 LLM은 정량 특징을 바탕으로 `shape_analysis`, `element_analysis`, `stroke_analysis`, `overall_description`과 3~8개의 검색 키워드를 생성합니다. 이미지와 Base64는 직접 입력하지 않습니다.

## 2. 인덱싱

- 정량 특징 벡터는 RDBMS에 저장합니다.
- 자연어 설명/키워드의 임베딩은 별도 텍스트 벡터 인덱스에 저장합니다.
- 정량 저장 실패 시 Active 전환을 차단합니다.
- 텍스트 인덱싱 실패 시 `NumericOnly`를 허용할지는 정책 확정이 필요합니다.

## 3. 파츠 탐색

### 하드 필터

먼저 `weapon_type`, `weapon_subtype`, `part_type`, `anchor_points`, 접합 방향과 연결 조건이 맞지 않는 후보를 제거합니다.

### 정량 검색

`cv_metrics`를 고정 순서의 정규화 float array로 만들고, 항목별 가중치를 적용한 weighted distance를 인메모리에서 계산합니다.

> 정량 검색에는 별도 MLP 인코더나 vector DB를 사용하지 않습니다.

### 의미 검색

검증된 `overall_description`, `keywords`와 분석 문장을 임베딩해 별도 텍스트 벡터 인덱스에서 검색합니다.

### 결과 통합

정량 검색과 의미 검색을 병렬 실행한 뒤 후보 합집합에 \*\*Reciprocal Rank Fusion(RRF)\*\*을 적용합니다. 상위 후보만 정량 특징으로 재비교하고 다음 요소를 결합해 `final_score`를 산출합니다.

- numeric similarity
- semantic similarity
- keyword similarity

최고 점수가 `MIN_FINAL_SCORE` 이상이면 자동 선택합니다. 동점은 numeric → semantic → keyword → `part_id` 오름차순으로 결정합니다.

## 4. 자동 조립

1. `parts_assembly`와 기준 캔버스를 조회합니다.
2. 필수 파츠가 모두 존재하는지 확인합니다.
3. 기준 파츠를 배치합니다.
4. 각 파츠의 `anchor_point`를 접합 관계에 맞춰 연결합니다.
5. 기본 `position`, `scale`, `rotation`에 스케치 분석 보정값을 허용 범위 내에서 적용합니다.
6. `draw_order`를 적용합니다.
7. 투명 배경의 `assembled_weapon_asset`으로 합성합니다.
8. 실제 조립 데이터를 저장하고 검증합니다.

## 5. 미확정 파라미터

- `CV_METRIC_WEIGHTS`
- `NUMERIC_SEARCH_TOP_K`
- `SEMANTIC_SEARCH_TOP_K`
- `RRF_CANDIDATE_LIMIT`
- `RERANK_TOP_K`
- `MIN_FINAL_SCORE`
- 텍스트 임베딩 모델
- `NumericOnly` 활성 정책
- 조립 transform 보정 허용 범위

상세 미확정 목록은 [결정 필요 항목](/project/decisions)에서 관리합니다.
