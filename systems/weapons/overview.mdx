# 무기 시스템

## 1. 개요

무기 시스템은 완성 무기의 **대종류/세부 종류, 파츠 구조, 등록 파츠 자산, 형태 특징, 접합 규칙과 조립 데이터**를 관리합니다. 플레이어가 실제로 그려 제작하는 흐름은 [무기 제작 시스템](/systems/crafting/overview)이 담당합니다.

## 2. 현재 기준

- 플레이어는 **무기 대종류만 직접 선택**합니다.
- 세부 무기 종류는 스케치 분석 결과를 기반으로 시스템이 자동 판정합니다.
- 무기는 필수/선택 파츠로 구성할 수 있습니다.
- 파츠마다 검색용 형태 특징과 조립용 접합점을 사전 정의합니다.
- 자동 조립을 기본으로 하며 플레이어가 파츠를 직접 조정하는 제작 방식은 핵심 루프에 포함하지 않습니다.

## 3. 용어

| 개념 | 설명 |
| --- | --- |
| `weapon_type` | 검, 창 등 상위 무기 분류 |
| `weapon_subtype` | 대검, 단검, 장창 등 세부 분류. 시스템 자동 판정 |
| `fixed_parts` | 무기를 만들기 위해 필요한 필수 파츠 종류 |
| `shape_features` | 등록 파츠의 정량 형태 특징 |
| `anchor_points` | 파츠끼리 연결하는 정규화 접합 좌표 |
| `parts_assembly` | 파츠 배치, 연결, 크기, 회전, 출력 순서 규칙 |
| `edited_part_asset` | 테마/원소 영향을 반영한 편집 파츠 |
| `assembled_weapon_asset` | 조립이 완료된 최종 무기 자산 |

## 4. 시스템 흐름

```text
무기 대종류 + 스케치 분석 결과
→ 세부 무기 종류 자동 판정
→ 필수/선택 파츠 종류 조회
→ 조립 호환 후보 필터링
→ 형태/의미 유사 파츠 검색
→ 최종 파츠 자동 선택
→ 원소/테마 영향 적용
→ anchor 기반 자동 조립
→ 조립 검증
→ 완성 무기 반환
```

## 5. 파츠 검색 원칙

1. 무기 종류, 파츠 종류, 접합 조건으로 후보를 하드 필터링합니다.
2. OpenCV/수학 기반 정량 특징으로 후보를 비교합니다.
3. 형태 설명/키워드의 의미 검색 결과를 보조 신호로 사용합니다.
4. 통합 순위 상위 후보를 다시 정량 비교해 최종 후보를 선택합니다.

구체 검색 알고리즘과 파라미터는 [무기 모듈 기능정의](/systems/weapons/module)에서 관리합니다.

## 6. 자동 조립

선택된 파츠는 `parts_assembly`에 정의된 기준 파츠, 접합 관계, `position`, `scale`, `rotation`, `draw_order`를 기반으로 자동 조립합니다.

검증 실패 조건 예시는 다음과 같습니다.

- 필수 파츠 누락
- 접합점 불일치
- 허용 범위를 벗어난 위치/크기/회전
- 캔버스 이탈
- 비정상 공백 또는 겹침

## 7. 콘텐츠와 기능의 분리

- 실제 무기 대/소분류 및 파츠 목록: [무기 콘텐츠 정의](/systems/weapons/content)
- 분석/검색/조립의 구현 단위: [무기 모듈 기능정의](/systems/weapons/module)

## 8. Deprecated 규칙

구 무기 기획서의 **대분류+소분류 직접 선택** 정책과 **이미지/LLM 직접 스케치 해석으로 읽힐 수 있는 설명**은 현재 기준에서 폐기합니다. 현재 기준은 세부 종류 자동 판정 및 VLM 미사용입니다.

## 9. 확정 필요 항목

- 파츠 검색 점수 가중치
- 임베딩 모델
- 후보 수/재정렬 수/최소 점수
- 조립 보정 허용 범위
- 파츠별 필수 형태 특징의 최종 집합
